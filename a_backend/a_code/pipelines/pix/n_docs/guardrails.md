# Guardrails de Documentação

## Regras

- Usar linguagem formal, técnica e objetiva.
- Não usar emojis.
- Documentar fontes públicas utilizadas.
- Não afirmar economia real comprovada quando o cálculo for hipotético.
- Diferenciar análise observada de cenário estimado.
- Manter README e PRDs atualizados quando novos artefatos forem criados.
- Registrar limitações, premissas e riscos de interpretação.
- Não incluir credenciais, tokens, dados privados ou informações sensíveis.

## Aplicação no Projeto

As seções de README, PRDs, matriz de aderência e notebooks devem deixar claro que os modelos e estimativas são educacionais e não devem ser usados como análise financeira oficial.

## Guardrail Doc Final

- Usar linguagem formal, tecnica e objetiva.
- Nao usar emojis.
- Documentar fontes publicas utilizadas.
- Separar fatos observados de hipoteses analiticas.
- Nao afirmar economia real comprovada.
- Registrar que economias sao estimativas baseadas em cenarios.
- Manter README, PRDs, matriz e documentacao de agents/skills atualizados.
- Registrar MCPs nao implementados como evolucao futura, sem sugerir que estao ativos.
